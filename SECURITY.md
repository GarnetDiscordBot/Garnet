# Garnet Security Policy

**Last updated: 1 October 2026**

## Reporting a Security Issue

If you believe you have found a security vulnerability in Garnet, please report it privately rather than publicly disclosing the vulnerability.

Use the official Garnet support or security contact once one has been established.

Please include:

- A clear description of the issue.
- The affected feature or component.
- Steps needed to reproduce the issue, where safe to provide.
- Any relevant logs or screenshots that do not contain sensitive information.
- The potential impact of the issue.

## Responsible Disclosure

Please give the Garnet team reasonable time to investigate and address a reported vulnerability before publicly disclosing technical details.

Do not access, modify, delete, or disclose data that does not belong to you while investigating a potential vulnerability.

## Scope

This policy applies to the publicly available Garnet services and components explicitly identified by the Garnet team as being within scope.

The Garnet source code is currently maintained in a private repository.

## Security Updates

Security fixes may be released as part of normal Garnet updates. The details disclosed publicly will depend on the nature and severity of the issue.
